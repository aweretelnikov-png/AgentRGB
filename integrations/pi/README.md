# AgentRGB для Pi

Pi package автоматически подключает lifecycle-индикацию и при необходимости запускает локальный AgentRGB Core. Нужны Windows, Python 3.14+ и установленный Python-пакет AgentRGB; команда `agentrgb` должна быть в PATH процесса Pi. Расширение не устанавливает Python-пакет само.

Из корня репозитория:

```powershell
python -m pip install -e .
pi install ./integrations/pi
pi list
pi
```

Без сохранения установки: `pi -e ./integrations/pi`. После установки не добавляйте одновременно `-e ./integrations/pi/agentrgb.ts`, чтобы не регистрировать интеграцию дважды.

Публичная установка после production publish:

```powershell
py -3.14 -m pip install agentrgb
pi install npm:agentrgb-pi
pi
```

Текущая версия Pi package — `0.1.0`; финальные Python/npm артефакты ещё не опубликованы.
Python RC `0.1.0rc1` проверен из TestPyPI, Pi RC `0.1.0-rc.1` — из npm.
Пока npm `latest` и `next` указывают на `0.1.0-rc.1`; удаление `latest` вернуло E400,
повтор не выполнялся. При будущей финальной публикации `latest` должен перейти на `0.1.0`.
До неё команды выше не подтверждают доступность финального release.
Auto-start выбирает `aula-f75`: для fake owned-Core smoke используется временный
launcher, который проверяет аргументы, выбирает `fake` и блокирует HID.

## Запуск и остановка

На `session_start` расширение проверяет `/health` на `127.0.0.1`, порт задаётся `AGENTRGB_PORT` (по умолчанию `8765`). Существующий Core используется без владения. Иначе запускается `agentrgb start --output aula-f75`, без shell и вывода в TUI. Ожидание готовности ограничено пятью секундами после первой health-проверки (до 300 мс на запрос, пауза 100 мс). При ошибке интеграция отключается до следующего запуска Pi; в UI выводится одно уведомление. События до готовности пропускаются, очередь/retry не добавлены.

На `session_shutdown` прекращается отправка событий. Только собственному child закрывается stdin; Core штатно освобождает output и listener. Через 1,5 с допускается принудительное завершение собственного процесса (на Windows — его дерева), затем ожидание ещё до 1,5 с. Повторный shutdown безопасен. Существующий внешний Core не останавливается.

В гонке двух запусков проигравший child завершается, а расширение повторно проверяет health и подключается к победителю как к внешнему Core. Владение подтверждается приватным сигналом готовности child после bind. Если Pi-владелец завершён, другие Pi теряют Core: полноценное управление временем жизни для нескольких клиентов отложено. Перезапускающего supervisor нет.

**Pi package auto-start в v0.1 рассчитан на проверенную AULA F75 configuration.** Для программной проверки заранее запустите `agentrgb start` (fake) или используйте test harness; автоматический выход пакета остаётся `aula-f75`. Автозапуск с реальным Pi может управлять клавиатурой при поступлении событий.

Extension передаёт только разрешённые lifecycle metadata, не читает содержимое запросов, ответов и инструментов. Semantics `working/waiting/completed`, идентификаторы и best-effort HTTP сохранены.

Manifest и peer dependencies оформлены по [Pi Packages](https://pi.dev/docs/latest/packages); ресурсы запускаются через [session lifecycle](https://pi.dev/docs/latest/extensions), а не в factory.
