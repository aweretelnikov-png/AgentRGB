# Границы первой версии

## Целевая среда

- Windows.
- Один локальный компьютер.
- Локальный процесс AgentRGB.
- Без облачной части, учётных записей и внешней передачи содержимого диалогов.

## Входит в MVP

### Источники

- Pi coding agent с `pi.dev`.
- Нормализация только подтверждённых структурированных событий.
- Допустимая частичная поддержка состояний источником, если его интерфейс не позволяет надёжно определить состояние.

Первый сквозной путь MVP — состояние Pi → ядро AgentRGB → прямой HID-адаптер AULA F75. Codex исследован, но отложен: для обычного Desktop не подтверждена пассивная граница lifecycle хода без изменения пользовательского workflow.

### Модель

- Постоянные состояния активности: `idle`, `working`, `waiting`.
- Временные сигналы: `completed`, `interrupted`, `error`.
- Источник-независимое окончание логического запуска `run_ended`, которое снимает активность даже без терминального сигнала.
- Необязательная классификация исхода; `unknown` не имеет цвета и не является отдельным состоянием активности.
- Отдельный жизненный цикл сеанса и активного запуска внутри сеанса.
- Общее постоянное состояние системы с приоритетом `waiting > working > idle`.
- Возврат к актуальному постоянному состоянию после временного сигнала.

Три терминальных сигнала — возможности общей системы; конкретный источник не обязан поддерживать все три. Неизвестная причина завершения снимает активность без сигнала. Это корректное поведение, а не ошибка AgentRGB.

### Профиль Pi первой версии

Основание: [результаты фазы 02](../experiments/pi-events/RESULTS.md) для `@earendil-works/pi-coding-agent 0.85.1` и [сквозной 04C](../experiments/phase-04c/RESULTS.md) для установленного Pi 0.86.1 в проверенном окружении Windows. Production Pi extension реализован и подтверждён в одной полной аппаратной цепочке.

Поддерживаются:

- `working` по `agent_start`;
- `waiting` по блокирующему `ctx.ui` prompt внутри активного логического запуска;
- возврат `waiting → working` при окончании UI-ожидания, если запуск ещё активен;
- окончание активности по `agent_settled` независимо от известности исхода;
- `completed`, только если последний assistant последнего низкоуровневого запуска имеет `stopReason=stop` и после этого приходит `agent_settled`.

Не поддерживаются `interrupted`, run-level `error` и `waiting` по обычному текстовому вопросу модели. `completed` означает обычный способ окончания выполнения, а не успешность задачи. `agent_settled` сам по себе не означает `completed`.

Реальные provider retry, compaction, resume/fork не проверены. Они сознательно не блокируют первую реализацию с указанным профилем и не объявляются полностью поддержанными. Очередь сообщений проверена внутри текущего запуска; она не обязана создавать новый `agent_start`. Текущий Pi adapter создаёт UUID для каждого логического запуска; подробности и границы — в [INTEGRATIONS.md](INTEGRATIONS.md).

### Индикация

- `idle` — AgentRGB не вмешивается в пользовательскую подсветку.
- `working` — одноцветный синий на AULA F75.
- `waiting` — одноцветный жёлтый на AULA F75.
- `completed` — короткий зелёный сигнал.
- `interrupted` — короткий оранжевый сигнал.
- `error` — красный временный сигнал.
- `waiting` имеет приоритет над временными сигналами и немедленно прекращает текущий сигнал.
- Терминальные события, полученные во время активного `waiting`, не показываются и не откладываются.
- Первая версия не содержит очереди отложенных временных сигналов.
- Цвета и эффекты представлены как правила, которые позднее можно вынести в настройки.

### Вывод

- Первая целевая периферия — AULA F75 по USB.
- Первый выход — прямой HID-адаптер AULA F75.
- Поддерживаемая аппаратная конфигурация: AULA F75, USB, `258A:010C`, проверенный vendor HID-интерфейс `MI_01/COL06` с usage page `0xFF00`.
- Реальный выход включается только явным `--output aula-f75`; стандартный выход — `fake`.
- Production-адаптер использует volatile Direct-кадры `0x06/0x08` с целевым интервалом 50 мс и прекращает их при освобождении устройства. Persistent-команды `0x04/0x0A` production lifecycle не отправляет; их прежнее применение сохранено в исторических экспериментах. H5 подтвердил обычный production-цикл на устройстве, H6 — штатный shutdown, H7 — остановку worker при контролируемой программной ошибке с живым Core и самостоятельным возвратом пользовательского профиля.
- OpenRGB не входит в обязательный путь MVP и остаётся будущим универсальным выходным адаптером для совместимых устройств.
- Отсутствие другого приложения, которое одновременно и постоянно перезаписывает подсветку выбранного устройства.
- Проверка точного HID-интерфейса, объявленного report ID `06`, model `03` и PSD `00CD` перед Direct-кадрами.
- Использование только тех команд изменения RGB, которые отдельно подтверждены экспериментом на целевом устройстве.
- Постоянная индикация AgentRGB.
- Временный сигнал с возвратом к актуальной индикации AgentRGB.
- Остановка heartbeat и закрытие HID handle при штатном освобождении устройства и завершении программы; аппаратный профиль возвращается по timeout контроллера, как наблюдалось в D2.
- Без обещания побайтного восстановления неизвестных частей аппаратного профиля.
- Без гарантии полного восстановления после аварийного завершения процесса AgentRGB.

### Эксплуатация

- Локальная диагностика без содержимого запросов и ответов.
- Корректное завершение с остановкой Direct heartbeat и освобождением устройства.
- Изоляция внутренних ошибок AgentRGB от семантического состояния агентов.
- Best-effort-доставка событий: неисправность AgentRGB или RGB-стека не влияет на выполнение агента.

## Не входит в MVP

- Адаптер Codex и индикация обычного Codex Desktop.
- Управление AULA F75 по 2,4 ГГц или Bluetooth.
- Разные зоны или устройства для отдельных агентов.
- Графический редактор анимаций.
- Сложный графический интерфейс.
- Мобильное приложение.
- Облачный сервер, авторизация и синхронизация компьютеров.
- Philips Hue и Home Assistant.
- Анализ содержания запросов и ответов.
- Определение успешности выполнения по тексту.
- Сложное распознавание текущей деятельности агента.
- Большой каталог интеграций и магазин сценариев.

## Не обещается первой версией

- Доставка каждого события при аварийном завершении процесса-источника.
- Точное воспроизведение всех аппаратных эффектов устройства после восстановления.
- Одинаковые возможности прямого HID-адаптера и будущего адаптера OpenRGB.
- Семантика `error`, если источник не предоставляет однозначного структурированного события.
- Поддержка неизвестных версий протоколов без явной проверки совместимости.
- Точное отображение состояния, которое источник не подтверждает надёжным структурированным событием.

## Условия завершения MVP

MVP считается готовым, когда на поддерживаемой конфигурации Windows подтверждены следующие сценарии:

1. Pi переводит подтверждённый активный запуск в `working`.
2. Подтверждённые Pi начало и окончание UI-ожидания обрабатываются без таймерных догадок.
3. Подтверждённое окончание запуска Pi снимает активность даже при неизвестном исходе. Поддержанный исход создаёт временный сигнал, если это допускает политика приоритетов; после сигнала возвращается актуальная постоянная индикация.
4. При отсутствии активной индикации Direct heartbeat прекращается, устройство освобождается, и проверенная F75 самостоятельно возвращает пользовательский профиль.
5. Ошибки выходного адаптера, транспорта и интеграции диагностируются, но не становятся `error` агента.
6. Завершение AgentRGB инициирует остановку heartbeat и закрытие HID handle без restore-команд.
7. Если AgentRGB, локальный приёмник, выходной адаптер или устройство недоступны, Pi продолжает работу, не ожидая восстановления индикации.

На проверенной конфигурации Windows + Pi 0.86.1 + USB AULA F75 перечисленные
условия первой сквозной версии выполнены: [04A](../experiments/phase-04a/RESULTS.md)
подтвердила Pi lifecycle, неизвестный исход и Core-down с `FakeOutput`,
[H5–H7](../experiments/phase-04b/H7-RESULTS.md) — production Direct Mode,
штатное завершение и контролируемый сбой output, а
[04C](../experiments/phase-04c/RESULTS.md) — единую цепочку реального Pi до
физической F75 и самостоятельный возврат профиля. Это закрывает проверку
первого пути MVP для указанной конфигурации; best-effort transport, другие
версии Pi и аварийное завершение процесса остаются ограничениями.
