# Pi: исследование событий, фаза 02

Эксперимент для Pi `0.85.1`, Node.js `v24.15.0`. Не адаптер AgentRGB.
Выходов RGB, транспорта, нормализации и генерации `run_id` нет.

## Запуск

Из корня репозитория в отдельном интерактивном PowerShell:

```powershell
./experiments/pi-events/start-tui.ps1 -Scenario A
```

Меняйте `-Scenario` согласно таблице. Каждый вызов создаёт отдельный каталог
`results/<сценарий>-tui-<время>`. После сценария штатно выйдите из Pi через `/quit`.
Расширения подключаются временно через `-e`; автозагрузка остальных ресурсов отключена.
`--no-session` запрещает сохранение экспериментального диалога Pi.
Не используйте для опыта существующую беседу или личные файлы.

Если в вашей среде нужен прокси, задайте HTTP_PROXY/HTTPS_PROXY в запускающем
PowerShell: скрипты наследуют окружение. Адрес прокси в файлы проекта не включается.
При запуске из песочницы учтите: Pi создаёт lock-файл рядом с хранилищем авторизации
даже для чтения. Запрет записи туда может проявляться как `No API key`, хотя
в обычном терминале модель работает. Не копируйте ключи в эксперимент для обхода.

| Сценарий | Действие в Pi | Что наблюдать |
|---|---|---|
| A | «Ответь OK без инструментов». | Число start/end/settled, `isIdle` |
| B | «Прочитай только fixture.txt инструментом read один раз, затем ответь OK». | tool_call/result внутри запуска |
| D | «Используй ask_user_question один раз: предложи выбрать между Да и Нет для безвредного теста. После ответа пользователя напиши OK». | Не отвечать 5–10 секунд, затем выбрать ответ; продолжение и settled |
| D-idle | Команда `/pi-events-idle`; не отвечать несколько секунд, затем любой ответ | UI span без agent_start; модель не нужна |
| E | «Выполни bash-команду node -e 'setTimeout(() => {}, 20000)' ровно один раз, затем ответь OK». | Во время работы инструмента вручную нажать штатный Escape / app.interrupt |
| F | «Прочитай read ровно один раз missing-fixture-intentionally-absent.txt. После ожидаемой ошибки ответь OK, не повторяя чтение». | isError=true и дальнейшая работа |
| G | Та же безвредная пауза, что в E; во время инструмента вручную поставить «Теперь ответь OK без инструментов» в очередь follow-up штатным сочетанием Pi | Pending messages, число низкоуровневых запусков, отсутствие промежуточного settled |

Для E/G нужен доступный Pi bash; при его отсутствии эти сценарии остаются непроверенными.
Для G используйте очередь follow-up (`Ctrl+Q` на Windows или `Alt+Enter` по
документации Pi 0.85.1; пользовательские переназначения имеют приоритет).
Не отправляйте второй независимый запрос после settle. Регистратор видит
hasPendingMessages, но не различает steering и follow-up.
Не вызывайте retry или compaction искусственно.

Для D дополнительно отметьте вручную: появилось ли окно, когда ответили,
продолжил ли агент работу. Timestamp регистратора не доказывает порядок отрисовки UI.
Для E отметьте, что прерывание выполнено именно во время операции, а не в idle.
Не сохраняйте скриншоты с содержимым личных бесед.

Без UI можно повторить A/B/F в print mode:

```powershell
$piCli = Join-Path (npm root -g) '@earendil-works/pi-coding-agent/dist/bundle/cli.js'
node ./experiments/pi-events/run-print.mjs A $piCli
node ./experiments/pi-events/run-print.mjs B $piCli
node ./experiments/pi-events/run-print.mjs F $piCli
node ./experiments/pi-events/run-print.mjs A $piCli json
```

В print stdout модели отбрасывается. В JSON mode сохраняются только типы
событий lifecycle и willRetry из agent_end в отдельный wire-lifecycle.jsonl;
никакие объекты сообщений не копируются в результат. stderr преобразуется только в категории известных
ошибок запуска, без сохранения текста. `process.json` содержит код выхода и
диагностику запуска, а не терминальное состояние AgentRGB. Тайм-аут 90 секунд
означает неполный опыт, а не прерывание пользователем или `completed`.

## Регистратор и приватность

`pi-event-recorder.ts` подписывается на 13 основных событий и три события
compaction. Поля извлекаются по разрешённому списку; объекты событий не копируются.
`sessionId` берётся только через `getSessionId()`, без чтения записей сеанса.
`turnIndex` — локальный индекс Pi, `toolCallId` — идентификатор вызова инструмента.
Поле `sequence` принадлежит регистратору и не является идентификатором запуска.

В дополнительном опыте разрешён enum `stopReason`: на `turn_end` он берётся
из assistant message, на `agent_end` — из последнего assistant данного
низкоуровневого запуска. Структурированный `role` читается только для выбора
сообщения и не сохраняется. Не читаются content, thinking, errorMessage,
`toolResults`, title, prompt, текст, аргументы инструментов, пути и содержимое
файлов. Объекты сообщений не сериализуются. `willRetry` для
agent_end записывается только при наличии; в extension API 0.85.1 его нет.
`ui_prompt_end` записывается как факт, без ответа пользователя и title.

Запись асинхронная, с ограничением очереди 1024 записи. При ошибке или переполнении
наблюдатель отключает запись и сообщает фиксированную диагностику без исключения.
Он не возвращает решений обработчикам Pi. На штатном shutdown даёт записи до
500 мс на завершение. При аварийном завершении последние записи могут потеряться.
Отсутствие ожидаемого события в неполном логе не доказывает его отсутствие в Pi.
Обычные накладные расходы обработчика и файловой системы остаются; полной
невлиятельности на тайминги эксперимент не обещает.

Результаты — только очищенные JSONL. Не перенаправляйте сырой stdout JSON/RPC
в репозиторий: он содержит сообщения и параметры инструментов.

## Проверки

```powershell
node --test ./experiments/pi-events/recorder.test.mjs
```

Тесты проверяют запрет чтения приватных полей и их отсутствие в реальном JSONL,
выбор stopReason без возврата к ранней причине, порядок записей, штатный flush
и отсутствие исключений в источник при ошибке записи. Это тесты регистратора,
а не доказательство последовательностей реального Pi.
