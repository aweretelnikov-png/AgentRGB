## Единственный физический запуск

Запущен только `node ./experiments/phase-04c/run.mjs aula-f75` с жёсткими
пределами 150 секунд и 3000 попыток Direct frame. Pi показал настоящий
блокирующий `ctx.ui.confirm`; до подтверждения прошло **33,900 с waiting**,
то есть более требуемых пяти секунд. После ответа Pi вывел `OK` и завершился
через `/quit` с кодом 0. Общая работа listener заняла **67,912 с**; аварийные
пределы не достигнуты.

| Уровень | Подтверждённая последовательность |
|---|---|
| Pi | `agent_start → ui_prompt_start → ui_prompt_end → agent_end(stop) → agent_settled` |
| Adapter | `run_started → run_waiting → run_resumed → run_ended(completed)` |
| Core | `working → waiting → working → completed → idle` |
| Direct RGB | `0000FF → FFFF00 → 0000FF → 00FF00` |
| Визуально | Синий → жёлтый → синий → зелёный → самостоятельный возврат исходной статичной разноцветной подсветки |

Временные отметки UTC из [единого журнала](results/aula-f75-2026-09-24T07-16-14-751Z/journal.jsonl):

| Событие | Время UTC |

| `run_waiting` | 07:16:18.346 |
| `run_resumed` | 07:16:52.246 |

`completed` длился **1,997 с**. Было **608 попыток и 608 успешных** Direct
frames через один открытый handle: 72 синих, 506 жёлтых, 30 зелёных;
переключение на синий после waiting видно в порядке кадров. Первый и последний
кадры разделяют 40,697 с. В журнале нет HID/API ошибки, отказа output,
исчерпания budget или timeout. Wrapper пропускал только один read request
`0x82` и валидные production `0x06/0x08` кадры. Команды `0x04`, `0x0A`,
`0x39`, `0x3C`, disable и restore не отправлялись. После `idle` новых кадров
не было, heartbeat остановился, worker и handle закрылись; Core и listener
завершились, порт снова свободен.

[Машинная сводка](results/aula-f75-2026-09-24T07-16-14-751Z/summary.json)
имеет `status=passed`; [визуальное подтверждение пользователя](results/aula-f75-2026-09-24T07-16-14-751Z/visual-confirmation.json)
отдельно фиксирует все четыре цвета и самостоятельный возврат профиля.
Журнал содержит только технические события и идентификаторы. Pi recorder
работал после adapter, поэтому порядок близких timestamp не служит измерением
сетевой задержки.

## Вывод и границы

На проверенной конфигурации Windows + Pi 0.86.1 + USB AULA F75 первый
сквозной путь MVP подтверждён. Это один успешный опыт с best-effort HTTP
доставкой; он не даёт гарантии доставки при сбое Pi или сети и не расширяет
поддержку на другие версии Pi, устройства или аппаратные профили. При
аварийном завершении процесса автоматический возврат подсветки по-прежнему
не гарантирован. Следующих аппаратных опытов не было.
