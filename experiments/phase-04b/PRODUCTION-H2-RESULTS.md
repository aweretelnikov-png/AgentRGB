# Production H2: цвета прошли, визуальный restore не прошёл

23 сентября 2026 года. В одном production `AulaF75Output` acquire-cycle
с synthetic Core events выполнена последовательность
`working → waiting → working → completed → release`. Pi не запускался.
[Сводка и полные raw](results/production-h2-20260923T110606724480Z/)
сохранены. Перед первой записью на том же рабочем handle прошёл свежий gate:
`258A:010C`, `MI_01/COL06`, usage `FF00/0001`, feature 520, report ID `06`,
model `03`, PSD `00CD`, config `[66]=09`, `[67]=37`, RGB `FF0000`.
Исходные полные `0x82`/`0x84`/`0x8A` совпали с ранее восстановленным baseline.

| Шаг | Write | Read-back | Визуально |
|---|---|---|---|
| acquire | `0x04`, `[67] 37→30` | `0x84` валиден, `[66..67]=09 30` | Затем синий |
| working | `0x0A #0000FF` | `0x8A=0000FF` | Синий подтверждён |
| waiting | `0x0A #FFFF00` | `0x8A=FFFF00` | Жёлтый подтверждён |
| working | `0x0A #0000FF` | `0x8A=0000FF` | Синий подтверждён |
| completed | `0x0A #00FF00` | `0x8A=00FF00` | Зелёный подтверждён |
| color restore | `0x0A #FF0000` | `0x8A=FF0000`; весь raw равен исходному | — |
| config restore | `0x04`, полный snapshot | `0x84` и `0x8A` побайтно равны исходным | **Исходная переливающаяся подсветка не вернулась; подсветка не горит** |

Всего **7 изменяющих команд**, все `SetFeature` успешны, ровно в
разрешённом порядке. Для каждого состояния выполнен один обычный read-back;
полные raw сохранены до валидации. Повторных write, workaround sleep или reopen
между состояниями не было. Отдельный управляющий процесс завершился; его
loopback listener освобождён. После отрицательного визуального результата
дополнительных HID-команд и попыток «дочинить» профиль не выполнялось.

Офлайн-сравнение сохранённых raw: финальный `0x84` равен начальному по всем
520 байтам; `0x8A` после color restore и финальный `0x8A` также равны
начальному по всем 520 байтам. В частности, финальный config `[67]=37` и RGB
`FF0000`. Это **не подтверждает визуальное восстановление** в H2. Причина
неизвестна; возможна составляющая аппаратного состояния, которую `0x84/0x8A`
не отражают, но этот опыт не позволяет её установить. C1B с одним синим
переходом ранее давал визуальный restore; перенос этого результата на более
длинную последовательность оказался неверным.

Критерий успешного H2 **не выполнен**. Production `AulaF75Output` подтвердил
обычный state rendering четырёх переходов, но release для этого цикла
визуально не подтвердился. H3/H4 и 04C остаются заблокированными; Pi не
запускался. Production adapter не следует считать полностью валидированным
для обычного acquire-cycle до отдельного исследования restore. Коммита нет.

Последующий [read-only M-WAKE-1](MWAKE-RESULTS.md) зафиксировал тот же DARK
baseline; по одному `Fn+↓` и `Fn+↑` не изменили читаемые `0x84/0x8A` и не
включили подсветку. Дополнительных HID writes не было.

Позднее [read-only POWER](POWER-RESULTS.md) подтвердил, что полное физическое
обесточивание вернуло исходный переливающийся профиль **до первого чтения**,
хотя полные `0x82/0x84/0x8A` до и после остались побайтно одинаковыми.
