# D2: `0x06/0x08` без enable — успешный физический опыт

23 сентября 2026 года. Отдельно разрешённый D2 выполнен один раз на AULA F75
в Wired mode. Пользователь перед запуском подтвердил визуальный baseline:
`исходная статичная разноцветная подсветка`. Данные:
[burst summary и raw baseline](results/direct-d2-20260923T163834566887Z/summary.json),
[post-read summary и raw](results/direct-d2-post-20260923T163947408845Z/summary.json),
[побайтное сравнение](results/direct-d2-post-20260923T163947408845Z/comparison.json).

Перед первой изменяющей записью один fresh gate подтвердил: VID/PID
`258A:010C`, `MI_01/COL06`, usage `FF00/0001`, feature report 520,
объявленный descriptor feature report ID `06` на том же path hash, model
`03`, PSD `00CD`, config `[66..67]=09 37`, primary RGB `FF 00 00`.
Полные `0x82/0x84/0x8A` совпали с ранее сохранённым POWER baseline.
Raw 520-byte ответы сохранены до валидации.

[Сохранённый D2 кадр](results/direct-d2-20260923T163834566887Z/blue-frame.bin)
имеет 520 байт, header `06 08 00 00 01 00 7A 01`, ровно 122 тройки
`00 00 FF` в `[8..373]` и нулевой хвост `[374..519]`; SHA-256
`5446889ac334b8ad6722428f2fb583cc1a178709808679101e23c674a8cd5b54`.
Runner отправил **40** таких кадров через `HidD_SetFeature`; все 40 вызовов
Windows API завершились успешно, ошибок не было. Между вызовами задана
пауза 50 мс; фактический интервал начала вызовов по timestamp составил
примерно 61–63 мс с учётом времени API. От первого до последнего начала
прошло около 2,4 с. После последнего кадра handle закрыт; иных reports
не отправляли.

Пользователь визуально подтвердил одноцветный синий во время burst. После
прекращения кадров, **без disable, restore или иных изменяющих записей**,
самостоятельно вернулась `исходная статичная разноцветная подсветка` — по
оценке пользователя через несколько секунд. Точная задержка не измерялась.
Power cycle не потребовался.

Только после этого выполнено по одному обычному read-only циклу
`0x82`, `0x84`, `0x8A`. Все три полных 520-byte ответа **побайтно совпали**
со свежим baseline D2; diff offsets пусты:

| Ответ | SHA-256 до и после | Побайтно равны |
|---|---|---|
| `0x82` | `40d4fc0f4a1091627643a59dfbfd42eab89749b55c6ea15031e04a8703196523` | да |
| `0x84` | `5a90dd25a6dd82b2d639193ba2e03d9e3d98ae909dad32531ae0a1924cd413e0` | да |
| `0x8A` | `93f7fa0a46dc0c58f6bb5a117da5bd146a0933a598d48361c8425a0b51f286b5` | да |

Финальные model `03`, PSD `00CD`, config `[66]=09`, `[67]=37`, primary RGB
`FF0000`. Число изменяющих HID-команд AgentRGB: **40** — только кадры
`0x06/0x08`; `0x39=0`, `0x3C=0`, `0x04=0`, `0x0A=0`. Чтений: три цикла
до burst и три после визуального возврата.

**Вывод в пределах одного опыта:** на этой F75 `0x06/0x08` работает без
`0x39/0x3C` как volatile Direct Mode. Прекращение короткого heartbeat
вернуло штатный визуальный профиль без persistent restore, а читаемые
config/color остались baseline. Это подтверждает механизм-кандидат для
production runtime; надёжность при длительной работе, shutdown и ошибках
отдельно не проверялась. Production `AulaF75Output` не менялся. Повтор D2,
H3/H4, Pi и 04C не запускались. Коммита нет.

Перед аппаратным запуском прошли 119 Python и 12 Node тестов, включая fake
HID проверки строгого gate, лимита 40 кадров и остановки без retry.
