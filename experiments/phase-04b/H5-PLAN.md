# H5: ограниченный production Direct Mode цикл — только план

Этот план был подготовлен до физического опыта; [результат H5](H5-RESULTS.md)
сохранён отдельно. Скрипт `production_h5.py` использует существующие
`AulaF75Output` и `Core` с synthetic events. Он принимает уже созданный HID
backend извне, не имеет CLI и ничего не открывает при импорте. Физический
запуск требует отдельного разрешения.

Перед запуском пользователь подтверждает Wired mode и визуально видимую
`исходную статичную разноцветную подсветку`. Первый `working` вызывает
production `acquire`: fresh gate на `258A:010C`, `MI_01/COL06`, `FF00/0001`,
feature length 520, объявленный ID `06`, один `0x82` с model `03` и PSD `00CD`.
Значения пользовательских `0x84/0x8A` не ограничивают Direct Mode.

| Synthetic Core event | Цвет | Плановое время |
|---|---|---:|
| `run_started` | синий | 3,00 с |
| `run_waiting` | жёлтый | 3,00 с |
| `run_resumed` | синий | 3,00 с |
| `run_ended(completed)` | зелёный | 2,05 с |
| `tick → idle` | кадры прекращаются | сразу после сигнала |

Плановая активная длительность **11,05 с**; контрольный предел **12 с**.
Все исходящие reports пропускает экспериментальный `BudgetedHid`:
один read-only запрос `0x82`, не более **240** Direct-кадров `0x06/0x08`.
Любой иной report (`0x04`, `0x0A`, `0x39`, `0x3C` в том числе) отклоняется
до Windows HID. При достижении лимита 241-й кадр тоже отклоняется до HID;
worker останавливается. На каждом выходе из runner вызывается `Core.close()`.

Пользователь наблюдает последовательность `синий → жёлтый → синий → зелёный`,
а после остановки кадров — самостоятельный возврат исходной статичной
разноцветной подсветки через аппаратный timeout. Runner не посылает disable
или restore, не делает retry и не ждёт визуального возврата внутри `release`.
Время возврата и визуальные состояния фиксируются отдельно после опыта.

Свежая read-only идентификация при подготовке сохранена в
`results/production-h5-preflight-20260923T170319217566Z/identity.json`:
ID `06` объявлен, model `03`, PSD `00CD`, handle закрыт, изменяющих HID
записей **0**. Это подтверждает текущее устройство, но не заменяет fresh gate
непосредственно перед возможным H5.

H5, H6 и H7 завершены успешно; результаты H6 и H7 — в `H6-RESULTS.md`
и `H7-RESULTS.md`. Pi и 04C остаются заблокированы до отдельных решений.
