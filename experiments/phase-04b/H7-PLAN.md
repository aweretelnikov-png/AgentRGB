# H7: controlled heartbeat failure — исходный план

Физический опыт впоследствии выполнен успешно; фактический результат и журнал
см. в `H7-RESULTS.md`. Ниже сохранён план, подготовленный до отдельного
разрешения.

H7 проверит остановку production `AulaF75Output` при программной ошибке
**после** успешного Direct-кадра. Приватный `_after_direct_frame()` по умолчанию
ничего не делает. Только тестовый наследник подменяет его и один раз вызывает
`RuntimeError("h7_controlled_software_fault")`, когда счётчик успешных кадров
достигает **N = 20**. Исключение возникает в heartbeat worker после возврата
`backend.set_feature()`, вне Windows HID API и вне HID backend. Production
обработчик выставляет `heartbeat_failed`, останавливает worker и закрывает
handle best-effort. Публичной настройки fault injection нет.

## Предлагаемый будущий физический опыт

1. Подтвердить визуально исходную статичную разноцветную подсветку в Wired
   mode. Непосредственно перед первым кадром выполнить один fresh read-only
   identity gate: `258A:010C`, `MI_01/COL06`, usage `FF00/0001`, feature
   length 520, объявленный report ID `06`, model `03`, PSD `00CD`. Любое
   несовпадение означает **0 Direct-кадров и остановку**, без retry.
2. Через настоящий `EventServer → Core → AulaF75Output` подать один synthetic
   `run_started`. Один worker отправляет uniform blue `0x06/0x08` с обычным
   целевым интервалом 50 мс. Тестовый наследник инициирует fault ровно после
   20-го **успешного** кадра. Проверить визуально одноцветный синий.
3. Внешний аудитор ограничивает опыт **не более 3 секунд активного heartbeat**
   и **не более 60 Direct-кадров**. Если 20 успешных кадров не достигнуты,
   возникает API-ошибка или предел достигнут, остановиться без retry и
   дополнительных экспериментальных команд. Разрешённые изменяющие reports:
   только `0x06/0x08`; `0x04`, `0x0A`, `0x39`, `0x3C`, disable и restore — **0**.
4. После fault проверить завершение worker, закрытие handle, отсутствие
   новых кадров, живой HTTP listener и обработку `run_waiting`/`run_resumed`
   того же run через Core без нового hardware acquire. До следующего явно
   начатого цикла output не восстанавливается автоматически. Наблюдать
   самостоятельный возврат исходной статичной разноцветной подсветки без
   аппаратного reset.
5. Затем штатно завершить Core и закрыть listener. Сохранить временную
   последовательность успешных кадров, fault, worker stop, handle close,
   проверки Core и shutdown. После fault новых HID writes быть не должно.

Этот документ **не разрешает** физический H7. Его запуск требует отдельного
согласия после просмотра offline-тестов, свежего read-only identity и точного
write budget. Pi и 04C остаются закрытыми; commit не делать.
