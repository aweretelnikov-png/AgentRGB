# D1: остановка на первом enable, до Direct Mode

23 сентября 2026 года. Выполнен один отдельно разрешённый физический D1.
Перед запуском пользователь подтвердил Wired mode и исходную визуальную
переливающуюся подсветку. Данные: [summary и raw](results/direct-d1-20260923T143404505619Z/summary.json).

Один fresh read-only gate непосредственно перед первой изменяющей попыткой
прошёл: `258A:010C`, `MI_01/COL06`, `FF00/0001`, feature 520, report ID `06`,
model `[8]=03`, PSD `[12..13]=00CD`, config `[66..67]=09 37`, RGB
`[29..31]=FF 00 00`. Полные 520-byte `0x82/0x84/0x8A` побайтно равны
POWER-after baseline. Хеши соответственно:

```text
0x82 40d4fc0f4a1091627643a59dfbfd42eab89749b55c6ea15031e04a8703196523
0x84 5a90dd25a6dd82b2d639193ba2e03d9e3d98ae909dad32531ae0a1924cd413e0
0x8A 93f7fa0a46dc0c58f6bb5a117da5bd146a0933a598d48361c8425a0b51f286b5
```

После gate предпринята **ровно одна** изменяющая попытка: первый enable,
report ID `39`, полный аргумент 520 байт, начало `39 20 06 00 01 00 00 00`.
[Сохранённый аргумент функции](results/direct-d1-20260923T143404505619Z/enable-01-argument.bin)
восстановлен офлайн из того же builder; SHA-256
`79d8c18b7b9d83afaf7558debd34577ddaba6c7dc7837dbefe0fd92133a4b0cc`.
Это **не USB-capture**, а точные байты, которые runner передал Windows HID API.

`HidD_SetFeature` завершился ошибкой `WinError 87` («Параметр задан
неверно»). Подтверждённых успешных изменяющих записей — **0**, попыток —
**1**. Runner сразу остановился и закрыл handle. Второй/третий enable,
`0x08` blue frames, disable, `0x04`, `0x0A` и restore **не отправлялись**.
Следовательно, собственно Direct Mode и автоматический timeout этим опытом
не проверены; критерий успеха D1 не выполнен. Предписанный после успешного
blue read-only `0x82/0x84/0x8A` не выполнялся, поскольку blue не был
отправлен и правило первой ошибки требовало остановки без дополнительных
команд.

`WinError 87` сам по себе не различает неподдерживаемый report ID на
`MI_01/COL06`, несовместимую длину Windows `HidD_SetFeature` или другое
несоответствие параметров. Никакой вариант не проверялся повторной записью.
Следующий шаг может быть только отдельным read-only анализом HID report
descriptor/Windows collection и сопоставлением с WebHID источником; менять
длину, коллекцию или порядок по предположению нельзя. Production backend,
H3/H4, Pi и 04C не запускались. Коммита нет.

Визуальное состояние после остановки: пользователь подтвердил исходную
переливающуюся подсветку. Программное или аппаратное восстановление не
потребовалось; дополнительных HID-команд для проверки не отправляли.
