# POWER: визуальный профиль вернулся после полного обесточивания

23 сентября 2026 года. После production H2 подсветка была выключена,
несмотря на побайтно восстановленные читаемые config/color. Выполнен
read-only опыт до и после физического отключения питания клавиатуры.

В DARK-before model `[8]=03`, PSD `[12..13]=00CD`, config `[66]=09`,
`[67]=37`, primary RGB `FF0000`. Все три полных ответа по 520 байт
побайтно равны исходному H2 baseline. Handle закрыт до физического действия.

Пользователь подтвердил: клавиатура осталась в Wired mode, USB-кабель был
отключён так, что питание полностью пропало; Bluetooth и 2.4G не выбирались,
lighting shortcuts не нажимались. После повторного подключения **до первого
протокольного запроса** появился startup lighting, затем исходная
переливающаяся подсветка.

POWER-after прочитал только `0x82 → 0x84 → 0x8A`. Все ответы валидны, model
`03`, PSD `00CD`, config `[66..67]=09 37`, RGB `FF0000`; handle закрыт.
Побайтный diff DARK-before → POWER-after пуст для всех трёх полных 520-byte
ответов. POWER-after также побайтно равен исходному H2 baseline.

Оба этапа использовали только read requests `82,84,8A`; изменяющих HID-команд
AgentRGB — **0**. Физическое отключение питания выполнял пользователь.

Результат — сильное свидетельство того, что H2 оставил контроллер в
дополнительном runtime/volatile состоянии, не представленном известными
`0x84/0x8A`: полный аппаратный reset заново применил сохранённый профиль
без изменения этих читаемых данных. Конкретный отсутствующий apply/wake/latch
шаг не установлен. Release не исправлялся предположениями; новых HID writes,
lighting shortcuts, H2/H3/H4, Pi, 04C и factory reset не было. Следующий
этап, если он будет отдельно разрешён, — исследовать точные действия штатной
прошивки/OEM software при применении профиля. Коммита нет.
