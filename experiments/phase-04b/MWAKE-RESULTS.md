# M-WAKE-1: brightness-клавиши не разбудили подсветку

23 сентября 2026 года. После production H2 пользователь видел выключенную
подсветку. AgentRGB выполнил только семь read-only циклов:
`0x82, 0x84, 0x8A` для DARK baseline, затем `0x84, 0x8A` после одного
ручного `Fn+↓` и `0x84, 0x8A` после одного ручного `Fn+↑`.
[Все raw и диагностика](results/manual-20260923T111929413306Z/)
сохранены. Изменяющих HID-команд AgentRGB — **0**.

| Этап | Полный `0x84` относительно H2 baseline | Полный `0x8A` относительно H2 baseline | `[66..67]`, RGB | Визуально |
|---|---|---|---|---|
| DARK, до клавиш | Побайтно равен | Побайтно равен | `09 37`, `FF0000` | Подсветка выключена |
| После одного `Fn+↓` | Побайтно равен; diff пуст | Побайтно равен; diff пуст | `09 37`, `FF0000` | Подсветка осталась выключенной |
| После одного `Fn+↑` | Побайтно равен; diff пуст | Побайтно равен; diff пуст | `09 37`, `FF0000` | Подсветка осталась выключенной |

DARK `0x82` валиден: model `[8]=03`, PSD `[12..13]=00CD`; интерфейс —
`258A:010C`, `MI_01/COL06`, usage `FF00/0001`, feature report 520,
report ID `06`. Все ответы структурно валидны, handle закрывался после
каждого этапа. Ожидаемое `config[66]: 09→08` после `Fn+↓` **не произошло**;
после `Fn+↑` читаемые данные также не изменились.

Подсветка не проснулась. Поскольку штатное нажатие не произвело ожидаемого
читаемого изменения brightness, этот опыт не проверил гипотезу о возможном
дополнительном firmware-side apply/wake при таком изменении. Неизвестно,
почему клавиши в текущем состоянии не изменили `[66]`; делать вывод о
механизме wake нельзя. Дополнительных клавиш, HID writes, повторов H2,
H3/H4, Pi, 04C и factory reset не было. Production adapter не менялся,
коммита нет.
